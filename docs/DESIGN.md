# 设计取舍

## 1. 输入为什么是「久坐分钟」，不是 token 数

同类的拉屎插件用 token 驱动（说得多 = 拉得多）。痔的因果不是说了多少话，是**坐了多久**——一个人可以一整天不说话也照样坐出痔来。

所以唯一的输入源是 wall-clock 的坐姿时长：`user/message` 记起点，`turn/end` 结算，拿不到真实耗时才回落到 `sittingPerTurnMin`。上限 `maxSitPerTurnMin` 不是节流，是防挂机：夜里挂着会话，第二天早上不该突然疼到 100。

上下文压缩额外 +10 分钟，是同一个道理的现实映射——那说明你在这个窗口里连着干了很多轮，没起身。

## 2. 为什么三种型号必须是三种形状，不是三个数值

如果只是「疼得快 / 疼得慢」，用户选哪个都一样，只是程度不同，玩两次就腻。三种型号的差别在**惩罚的维度**：

- 内痔不动疼，动的是血和反应速度 → 它的破功方式是「慢半拍、说错词、脸白」，不是呻吟
- 外痔不动血，动的是锐痛和突然性 → 短句、倒吸气、话说一半
- 混合痔两样都来 → 允许语气在同一轮里翻转

所以 `VOICE` 是每型号一份的，不是共用一套再加系数。

## 3. 为什么内痔不许演疼

这是最容易写坏的地方。内痔没痛感，模型如果按「痔疮 = 疼」的刻板印象演，一开口就穿帮——熟悉这病的人一眼看出来。

代码层做了硬约束：`internal` 的 `VOICE` 第一句就是「你自己不觉得疼，所以别演疼」。它的注入块在 `blood < dizzyAt` 的时候甚至不进 `flare` 档。

## 4. 为什么每个会话一份状态

并行开三个会话干活是常态。如果共享一份身体，在 A 会话里坐了 3 小时，B 会话一开始就已经疼得说不出话——那不是沉浸，那是污染。

所以 `sessions/<sid>.json` 一会话一份，工具与注入都只读写当前 sid 的那份。子代理不参与（`header.parent` 直接跳过）——子代理不是「你」，它只是你派出去的手。

## 5. 注入为什么挂在 agent 的 scope，而不是全局 systemPrompt

全局注册会让所有会话都带这段文字，包括没开这个功能的。挂在 agent 自己的 `ctx.get('systemPrompt')` 上：

- 只影响这一个会话
- 关掉就是 detach，不用重建整个提示
- 状态文件留着，下次开还是这副身体（不是重置）

`order: 160` 是有意的：靠后但不压过收尾段，它只是背景噪声，不该抢正事的优先级。

## 6. 为什么 `blockFor` 要分 commit 与 preview

第一版里工具执行完也会调用一次 `blockFor()`，结果它把这一轮的注入 key 自己写掉了——等宿主真正来取 text 时，冷却与去重都判「说过」，于是**刚坐完三小时，这一轮一句话都不注入**。

修法是把「算」和「算数」拆开：工具/结算里 `commit: false` 只算一份快照，只有宿主真的调用 `text()` 才写 `lastInjectAt`。这条现在有回归测试（`坐 3 小时：外痔疼起来，注入块出现并带型号`）。

## 7. 为什么诡异档是 0–3 四档，不是滑杆

连续值会变成随机噪声：用户不知道 2.7 和 2.8 差在哪，模型也拿不到稳定的指示。四档每档一句明确的行为许可（允许一处细微 / 允许被打断 / 允许碎片），模型能照做，用户能预期。

`eeriness` 同时是**上限**：配置为 0 时，疼到 100 也不许有任何表现——这条也有测试。

## 8. 冷却与去重为什么不是「说过就永不再说」

压着不说会让语气断掉：疼了半小时，前十分钟怪怪的，后面突然恢复正常，像插件坏了。

所以同一状态最多压 `sameStateHoldFactor` 个冷却周期（默认 24 分钟），过了允许复述一遍。`flare` / `dizzy` / `treated` 不受冷却限制——那是「刚刚发生的事」，不是复述。

## 9. 没做的事

- **不做恶化警告**：提示模型「你该去看医生了」会立刻变成说教，破坏整个玩法。这是玩梗插件，不是健康 App。
- **不联网、不查资料**：所有文案是写死的，不随「最新医学共识」变。
- **不做连续疼痛曲线**：疼是阶跃的（发作顶一下），平滑曲线在文本里读不出差别。
- **不加每日上限**：这是角色状态，不是消耗品。真正的闸是「关掉」，不是配额。
